# HACKSPIRE: LUMINA — Database Schema
### 🆕 = added/changed from the latest dev-team meeting and Excel review. Auth stays custom (hashed password + JWT) for now — Supabase Auth fields are groundwork for a future migration, not active yet. Sponsors and contact info are hardcoded in the Flutter frontend — no DB tables for either.

## profiles
Extends Supabase's built-in `auth.users` — one row per login account, participant or admin.

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK, matches `auth.users.id` |
| name | text | |
| email | text | unique |
| student_staff_id | text | unique — used for dedup on Excel import |
| role | text | `participant` \| `admin` |
| first_login | boolean | default true, forces password change |
| hashed_password | text | current auth mechanism — password hash, checked against JWT-issued sessions |
| **username** | text | 🆕 unique, editable by the user |
| **email_verified** | boolean | 🆕 default false — not enforced yet under current auth; reserved for a future Supabase Auth migration |
| **reference_id** | text | 🆕 unique — comes pre-filled from the Excel import, not generated by the system |
| **university_name** | text | 🆕 nullable, free text — from Excel import or self-edited via profile |
| **technical_skills** | text | 🆕 nullable, free text or comma-separated tags |
| **preferred_role** | text | 🆕 nullable, e.g. "Frontend", "Design", "Pitching" |
| created_at | timestamptz | |

## teams

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| name | text | unique |
| **reference_id** | text | 🆕 unique, max 8 characters — format `GR_01`, `GR_02`... auto-generated, INCREMENTED FOR EACH GROUP via a Postgres sequence + trigger on INSERT |
| leader_id | uuid | FK → profiles.id — governs submission rights only, not team management |
| capacity | int | default 5, max 5, ≥ current member count |
| status | text | `open` \| `looking_for_teammates` \| `closed` \| `full` |
| approval_status | text | `pending` \| `approved` \| `rejected` |
| admin_note | text | nullable — set on rejection |
| locked | boolean | default false — true on admin approval, blocks writes |
| created_at | timestamptz | |

## join_requests
Unique constraint: one pending request per participant_id at a time. 🆕 Frontend requires a confirmation step before this row is created — UI-only, no schema impact.

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| team_id | uuid | FK → teams.id, ON DELETE CASCADE |
| participant_id | uuid | FK → profiles.id |
| status | text | `pending` \| `approved` \| `rejected` |
| created_at | timestamptz | |
| responded_at | timestamptz | nullable |

## submissions
🆕 Exactly 2 link fields — GitHub and a single Drive link (the Drive link contains both the infographic and pitch deck internally). Open to any team member, not leader-only.

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| team_id | uuid | FK → teams.id, unique, ON DELETE CASCADE |
| **github_url** | text | 🆕 nullable |
| **gdrive_url** | text | 🆕 nullable — single Drive link containing both required materials (infographic + pitch deck) |
| **submitted_by** | uuid | 🆕 FK → profiles.id — tracks which team member last submitted/edited |
| submitted_at | timestamptz | |
| updated_at | timestamptz | set whenever the submission is edited |

## timeline_items
🆕 Redefined to match the actual Excel structure — a full session + speaker schedule grouped by bootcamp phase, not a simple agenda list.

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| bootcamp_name | text | e.g. "Online Bootcamp 1", "Online Bootcamp 2", "Physical Bootcamp" |
| date_label | text | free text — source values are ranges like "13–15 Oct 2026", not single dates |
| time_session | text | raw "Time & Session" cell as-is, e.g. "2:10 PM – Keynote Session 1" |
| session_type | text | e.g. `Keynote` \| `Sharing` \| `Workshop` — open text, not a strict enum |
| speaker_name | text | nullable |
| speaker_bio | text | nullable |
| organization | text | nullable |
| session_description | text | nullable |
| speaker_photo_url | text | nullable |
| status | text | `TBD` \| `Proposed` \| `Confirmed` \| `Declined` — admin-facing, likely filtered out of the participant view |
| remarks | text | nullable — admin-only notes |
| order_index | int | for manual reordering after import |

| Column | Type | Notes |
|---|---|---|

| type | text | `join_request` \| `join_response` \| `announcement` \| `team_update` |
| reference_id | uuid | nullable — points to join_requests.id, announcements.id, or teams.id |
| message | text | |
| read | boolean | default false |
| created_at | timestamptz | |

## Relationships Summary
- profiles 1—N teams (as leader)
- teams 1—N team_members N—1 profiles — cascades on team delete
- teams 1—N join_requests N—1 profiles — cascades on team delete
- teams 1—1 submissions — cascades on team delete
- profiles 1—N submissions (as submitted_by)
- teams 1—1 finalists (optional)
- teams 1—1 winners (optional)
- profiles 1—N materials (as uploader)
- profiles 1—N announcements (as poster)
- profiles 1—N audit_log (as admin actor)
- profiles 1—N notifications (as recipient)
